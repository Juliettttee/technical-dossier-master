# Outline approval protocol

Provide the proposed report outline BEFORE drafting the final PDF.

Outline record: topic, objective, audience, sections (number, technical question, target evidence, hoped-for original figures, status), exclusion list, planned evidence threshold, known information gaps, recommended document length only if justified by material.

Show an action request: approve / change sections / change depth. Until an explicit approval, allow interviews, feasibility scans and outline edits, but DO NOT generate the final PDF. Record approval in session as `outline_approved: true` only after consent.

If credible sources show a central planned chapter is unsupportable, propose alternatives, update the outline, and ask again when the revision changes the user-approved scope materially.
